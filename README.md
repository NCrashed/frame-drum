# Бубен

Android-приложение для отработки ритмов на большом рамочном бубне. Вы задаёте
паттерн из ударов дум (центр), тек и ка (край), приложение ведёт метроном,
показывает, какой удар следующий, слушает бубен через микрофон и считает,
насколько точно вы попадаете.

## Сборка (Nix)

```sh
nix run .#build-apk     # → build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
nix run .#install       # собрать и поставить на телефон по adb
nix develop             # shell с flutter, JDK 17 и Android SDK
flutter test            # тесты детектора и подсчёта
```

Скриншоты экранов без телефона (в `test_screens/out/`):

```sh
nix develop -c sh -c 'SCREEN_FONT_DIR=$(nix build --no-link --print-out-paths nixpkgs#liberation_ttf)/share/fonts/truetype \
  SCREEN_ICON_FONT=$(dirname $(dirname $(readlink -f $(which flutter))))/bin/cache/artifacts/material_fonts/MaterialIcons-Regular.otf \
  flutter test test_screens --update-goldens'
```

## Как пользоваться

1. **Калибровка** (значок настроек на главном экране), один раз на телефон:
   - *Микрофон*: телефон в 1–2 м от бубна. Порог атаки такой, чтобы каждый
     удар давал ровно одну отметку.
   - *Дум и тек*: сыграйте 20 ударов по очереди, начиная с дума. По ним
     обучается классификатор именно для вашего бубна. Тек и ка на слух не
     различить, поэтому проверяется только дум против удара по краю.
   - *Задержка*: через динамик телефон сам слушает свои щелчки; в наушниках
     нужно сыграть дум под 16 щелчков. Поправка хранится отдельно для
     динамика, проводных и Bluetooth-наушников.
2. **Ритм**: выберите готовый (максум, баляди, саиди, мальфуф, упражнения) или
   создайте свой: деление доли (1/4, 1/8, триоли, 1/16), число долей, клетки
   нажатием или строкой вида `DT-T D-T-`.
3. **Занятие**: темп, щелчок (каждая доля, только начало цикла, без щелчка),
   «тишина» (например 2+2: два цикла со звуком, два без, проверка, держите ли вы
   темп сами), «подсказка звуком» (телефон играет сам ритм).
   - Круг изображает мембрану: дум на внутреннем кольце, тек и ка на внешнем,
     стрелка идёт по циклу. Ваши удары появляются там, куда реально попали:
     зелёные точно (±25 мс), жёлтые близко (±50 мс), оранжевые мимо, крестик
     означает лишний удар, красное кольцо вокруг точки означает не тот удар,
     красный круг на метке означает пропуск.
   - Полоса под кругом показывает последние удары на шкале ±100 мс;
     треугольник отмечает средний сдвиг.
   - **Точность**: доля нот, сыгранных в пределах ±50 мс. **Сдвиг**: средняя
     ошибка (минус значит спешите). **Разброс**: стандартное отклонение,
     главный показатель ровности. **Удар**: доля верно распознанных дум/тек.
   - После «Стоп» сессия попадает в историю (график точности и разброса).

Лучше всего заниматься в проводных наушниках. Через динамик микрофон слышит
щелчки самого приложения; они отфильтровываются по времени и громкости,
измеренной при калибровке, но тихий удар, совпавший со щелчком, может
потеряться.

## Как это устроено

- `android/.../AudioEngine.kt`: только ввод-вывод. `AudioTrack` с буфером
  200 мс крутит заранее отрендеренный буфер (вступление + цикл),
  `AudioRecord` (источник `UNPROCESSED`, если есть, иначе
  `VOICE_RECOGNITION`, чтобы не было АРУ) отдаёт куски по 10 мс. Оба потока
  привязаны к `System.nanoTime()` через `getTimestamp()`, поэтому время
  щелчка и время удара сравнимы напрямую. Задержка большого буфера не важна,
  её учитывают таймстемпы. Плагинов нет, как и в dice-checker.
- `lib/audio.dart`: `PlaybackClock` сглаживает таймстемпы воспроизведения и
  отличает дрожание от настоящих обрывов звука; обрывы показываются на экране
  занятия.
- `lib/dsp.dart`: детектор для большого бубна. Сигнал делится на 8 октавных
  полос; атака ищется по росту уровня в полосах с упором на верхние (там
  мембрана не звенит), причём подъём выше 1.4 кГц обязателен, иначе это
  биения мод. Время уточняется по верхним полосам, после удара действует
  рефрактерный период, зависящий от паттерна. Признаки удара: прирост уровня
  по полосам относительно 20 мс до удара (звон предыдущего дума вычитается)
  и форма спектра после него. Классификатор `StrokeModel` (гауссианы с общей
  дисперсией) обучается при калибровке.
- `lib/scoring.dart`: каждая атака привязывается к ближайшему ожидаемому удару
  в окне (половина кратчайшего промежутка между ударами, 40–150 мс).
- `lib/synth.dart`: щелчки и звуки бубна синтезируются в Dart.
- `test/drum_sim.dart`: модель 40-сантиметрового бубна для тестов (моды
  мембраны с долгим затуханием и биениями).

## Отладка на реальных записях

В калибровке включите «Записывать занятия». После каждого занятия рядом
появятся `session-*.wav` и `session-*.json`:

```sh
adb pull /sdcard/Android/data/dev.ncrashed.frame_drum/files/ recordings/
nix develop -c dart run tool/replay.dart recordings/session-....wav [порог_атаки] [тише_не_слушать]
```
